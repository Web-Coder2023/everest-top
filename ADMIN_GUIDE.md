# Руководство по управлению сайтом

Сайт не использует CMS. Контент меняется в исходных файлах, после чего нужно пересобрать сайт (`npm run build`) или запушить изменения в репозиторий, и Vercel соберёт его сам.

## Где что менять

| Что | Файл |
|---|---|
| Телефон, email, Telegram, домен, адрес формы, аналитика | `site.config.mjs` |
| Услуги в каталоге, категории, сценарии автоматизации, FAQ, проекты, этапы работы | `src/data/content.mjs` |
| Title, description, поисковые запросы страниц | `src/data/seo.mjs` |
| Тексты страниц (заголовки, абзацы, CTA) | `src/pages/*.mjs` |
| Меню, футер, cookie-баннер, форма, общие компоненты | `src/lib/ui.mjs` |
| Картинки на страницах | `public/images/` и вызовы `shot(...)` в `src/pages/*.mjs` |
| SVG-графика на «О студии» и «Контактах» | `src/lib/visuals.mjs` и `src/styles/visuals.css` |
| Цвета, шрифты, отступы, радиусы | `src/styles/variables.css` |
| Политика конфиденциальности | `src/pages/misc.mjs`, раздел `privacy` |

## Тексты

Главная — `src/pages/home.mjs`; «Услуги» — `services.mjs`; «Автоматизация» — `automation.mjs`; ИИ, сайты и цифровые продукты — `services-detail.mjs`; «Проекты», «О студии», «Контакты», политика и 404 — `misc.mjs`. Тексты лежат в обычных строках. Внутри строк допустим HTML (`<em>` выделяет слова градиентом).

Тексты не должны содержать выдуманных клиентов, цифр, отзывов и гарантий. `npm run check` ловит часть запрещённых клише, но не всё.

## Контакты

Меняйте значения в `site.config.mjs` (`phone`, `phoneHref`, `email`, `telegram`, `telegramHandle`). Номер для ссылки `tel:` пишется без пробелов, с плюсом.

## Добавить услугу в каталог

В `src/data/content.mjs`, массив `SERVICES`, добавьте объект:

```js
{ id: 'crm-setup', title: 'Настройка CRM', category: 'Автоматизация', icon: 'users',
  text: 'Краткое описание пользы для клиента.', href: '/services/business-automation/#what' }
```

- `category` должна совпадать с одним из значений `CATEGORIES`, иначе карточка не попадёт в фильтр.
- `icon` — название из `src/lib/icons.mjs`.
- Для главного направления добавляется `priority: true` (такая карточка одна).
- Новая категория добавляется в `CATEGORIES`, кнопка фильтра появится сама.

## Добавить проект

В `PROJECTS` добавьте объект (`id`, `ui`, `title`, `type`, `text`, `features`, `topic`). Поле `ui` задаёт вид мини-интерфейса: `requests`, `calc`, `bot`, `panel`, `docs`; новый вид добавляется в функцию `miniUI` (`src/lib/ui.mjs`).

**Реальный кейс.** Не используйте для него метку «Демонстрационный проект»: создайте отдельную функцию карточки без этой метки и добавляйте только подтверждённые данные (заказчик — с его согласия).

## FAQ

Массивы `FAQ_GENERAL`, `FAQ_AUTOMATION`, `FAQ_AI`, `FAQ_WEB`, `FAQ_PRODUCTS` в `content.mjs`: пары `{ q, a }`.

## SEO

Для каждого пути в `src/data/seo.mjs` заполните `title` (до 60–70 знаков) и `description` (60–170 знаков). У каждой страницы они должны быть уникальными: `npm run check` это проверяет. Поля `primary`, `secondary`, `intent` служат памяткой и в HTML не попадают.

## CTA

Кнопки создаются функцией `cta(label, topic, where)` из `src/pages/_shared.mjs`. `topic` (`automation`, `ai`, `web`, `products`, `other`) предзаполняет направление в форме, `where` попадает в событие аналитики. Не используйте одну и ту же подпись везде.

## Заменить или добавить картинку

1. Подготовьте файл 16:9 (например 1672×941, PNG или JPG).
2. `node scripts/optimize-images.mjs путь/к/файлу.png имя` создаст `public/images/имя-800.webp` и `имя-1600.webp`. Скрипту нужен пакет `sharp` (`npm i --no-save sharp`).
3. В нужной странице вызовите `shot('имя', 'Описание того, что на картинке')`. Для картинки в первом экране добавьте `{ priority: true }`.
4. Описание (alt) пишите по смыслу картинки, а не «картинка». Пустой alt проверка не пропустит.
5. Превью для соцсетей: `public/images/og.jpg`, 1200×630.

## Визуальные элементы

- Цвета и размеры — токены в `variables.css`.
- Положение панелей в hero — параметры `l`, `t`, `w` (проценты от рамки композиции) в `visuals.mjs`.
- Анимации — `animations.css`. Они отключаются при `prefers-reduced-motion`.

## Подключить отправку формы

1. Подготовьте endpoint, принимающий `POST` с `Content-Type: application/json` и ответом 2xx при успехе. Это может быть serverless-функция Vercel, сервис форм или ваш API.
2. Тело запроса:

```json
{ "name": "...", "contact": "...", "email": "...", "topic": "automation|ai|web|products|other", "message": "...", "page": "/contacts/" }
```

3. В Vercel добавьте переменную `FORM_ENDPOINT` с адресом и пересоберите сайт.
4. Если запрос не удался, посетитель увидит запасной вариант (Telegram, почта, копирование), а не ложное «отправлено».
5. Обновите раздел 4 политики конфиденциальности.

## Подключить аналитику

1. Переменные `ANALYTICS_SRC` (адрес скрипта счётчика) и `ANALYTICS_ID`.
2. Скрипт загрузится только после согласия посетителя на аналитику. События доступны через `window.evTrack(name, params)` и `dataLayer`.
3. Внесите подключённый сервис в раздел 5 политики.
4. Настройка конкретного счётчика (цели, события) делается на вашей стороне.

## Добавить новую страницу

1. Создайте файл в `src/pages/` по образцу, например `misc.mjs`: объект с `path`, `crumbs`, `body()`.
2. Добавьте запись в `src/data/seo.mjs`.
3. Подключите страницу в `scripts/build.mjs`: импорт и добавление в массив `pages`.
4. Добавьте ссылку в меню или футер (`src/lib/ui.mjs`), если нужно.
5. `npm run build && npm run check`.

## Сменить домен

Измените переменную `SITE_URL` в Vercel (или в команде сборки) и пересоберите. В файлах менять ничего не нужно.

## Перед каждой публикацией

```bash
npm run build && npm run check
```
