# Everest Digital — сайт

Многостраничный статический сайт цифровой студии Everest Digital. Главное направление — автоматизация бизнес-процессов.

## Важно: про стек

ТЗ предполагает Astro. При разработке в окружении не было Astro, а установка пакетов была отключена, поэтому сайт собран **собственным генератором на чистом Node.js без зависимостей** (`scripts/build.mjs`). Результат — обычная статическая папка `dist/`, которая публикуется на Vercel без изменений.

Структура сделана так, чтобы переход на Astro был простым: страницы, данные, UI-компоненты и стили разделены так же, как в предложенной структуре ТЗ. Если Astro для вас обязателен, скажите, и сайт можно перенести (страницы → `.astro`, функции UI → компоненты).

## Требования

- Node.js 18 или новее. Зависимостей нет, `npm install` не нужен.

## Команды

| Команда | Что делает |
|---|---|
| `npm run build` | Собирает сайт в `dist/` |
| `npm run dev` | Собирает и запускает локальный сервер на `http://localhost:4321` |
| `npm run check` | Проверяет собранный сайт: ссылки, якоря, title/description, h1, JSON-LD, запрещённые формулировки, id и aria |
| `npm run preview` | Запускает сервер для уже собранного `dist/` |

После изменений в `src/` запустите `npm run build` (или перезапустите `npm run dev`) и обновите страницу.

## Развёртывание на Vercel

1. Загрузите папку проекта в репозиторий GitHub.
2. В Vercel: **Add New → Project**, выберите репозиторий. Framework Preset: **Other**. Настройки сборки подхватятся из `vercel.json` (`npm run build`, папка `dist`).
3. В **Settings → Environment Variables** добавьте `SITE_URL` (например `https://example.ru`, без слэша в конце).
4. Подключите домен в **Settings → Domains** и повторите деплой.

## Домен

Production-домен задаётся переменной окружения `SITE_URL`. От неё строятся canonical, Open Graph, JSON-LD и `sitemap.xml`. Пока переменная не задана, используется заглушка `https://your-domain.example`, и сборка печатает предупреждение. **Старый адрес сайта не считается подтверждённым.**

Локально: `SITE_URL=https://example.ru npm run build`.

## Структура

```text
everest-digital/
├── public/               # favicon.svg, images/ (WebP-картинки страниц и og.jpg), копируется в dist как есть
├── scripts/
│   ├── build.mjs         # генератор: страницы → HTML, склейка CSS/JS, sitemap, robots
│   ├── dev.mjs           # локальный сервер
│   ├── check.mjs         # статическая проверка dist
│   └── optimize-images.mjs  # подготовка новой картинки (нужен sharp)
├── src/
│   ├── data/
│   │   ├── content.mjs   # услуги, сценарии, FAQ, проекты, этапы, демо-данные
│   │   └── seo.mjs       # title, description и поисковые запросы каждой страницы
│   ├── lib/
│   │   ├── ui.mjs        # компоненты: шапка, футер, кнопки, FAQ, вкладки, формы, демо
│   │   ├── visuals.mjs   # SVG-композиции: используются на «О студии» и «Контактах», остальные — запасные
│   │   └── icons.mjs     # иконки и логотип
│   ├── pages/            # home, services, automation, services-detail, misc (проекты, о студии, контакты, политика, 404)
│   ├── styles/           # variables, global, components, visuals, animations
│   └── scripts/main.js   # вся клиентская логика (около 20 КБ)
├── site.config.mjs       # контакты, домен, форма, аналитика
├── vercel.json
├── README.md
└── ADMIN_GUIDE.md
```

Дизайн-система описана в отдельном файле `EVEREST_UI_DESIGN_SYSTEM.md`, токены лежат в `src/styles/variables.css`.

## Картинки

Картинки страниц лежат в `public/images/` в двух размерах (`<имя>-800.webp` и `<имя>-1600.webp`, 16:9) и подключаются функцией `shot()`:

| Страница | Картинка | Где |
|---|---|---|
| Главная | `home-hero` | первый экран |
| Услуги | `services-hero` | первый экран |
| Автоматизация | `automation-hero`, `automation-flow` | первый экран и блок с интерактивной схемой |
| ИИ | `ai-hero` | первый экран |
| Сайты и веб-приложения | `web-hero`, `web-tech` | первый экран и блок «Техническая реализация» |
| Цифровые продукты | `products-hero` | первый экран |
| Проекты | `projects-hero` | первый экран |
| О студии, Контакты | SVG-композиции из `visuals.mjs` | первый экран |

`og.jpg` (1200×630) используется как превью при публикации ссылок. Первые экраны грузятся сразу, остальные картинки лениво, у всех заданы размеры, поэтому макет не прыгает. Чтобы заменить картинку, подготовьте её командой `node scripts/optimize-images.mjs файл.png имя` (нужен пакет `sharp`, он в проект не входит) и пересоберите сайт.

## Контакты

Телефон, email, Telegram и название студии — в `site.config.mjs`. Изменения попадают в шапку, футер, страницу «Контакты», политику и JSON-LD после пересборки.

## Форма обращения

Сайт статический, поэтому серверной части у формы нет, и **успешную отправку она не имитирует**. Пока `FORM_ENDPOINT` не задан, после проверки полей форма показывает готовый текст обращения и предлагает три честных способа: открыть Telegram с текстом, отправить по почте или скопировать.

Чтобы включить настоящую отправку, задайте `FORM_ENDPOINT` (URL вашего API, принимает POST с JSON). Подробности и формат — в `ADMIN_GUIDE.md`. После этого обновите раздел 4 в `/privacy/`.

## SEO

- У каждой страницы свой title, description, один h1, canonical, Open Graph, Twitter Card.
- JSON-LD: Organization, WebSite, WebPage (на «Контактах» ContactPage), BreadcrumbList, Service на страницах услуг. Рейтингов, отзывов, адресов и цен в разметке нет.
- `sitemap.xml` и `robots.txt` создаются при сборке, 404 в карту не попадает.
- Тексты и запросы страниц — в `src/data/seo.mjs`.

## Аналитика и cookie

Ничего стороннего не подключено. Баннер cookie сохраняет выбор в `localStorage`. Скрипт аналитики подключается, только если заданы `ANALYTICS_SRC` и `ANALYTICS_ID` **и** посетитель дал согласие на аналитику. События отправляются через `window.evTrack` и в `dataLayer`:

`cta_click`, `cta_secondary`, `telegram_click`, `phone_click`, `email_click`, `form_start`, `form_success`, `topic_select`, `filter_use`, `demo_view`, `demo_run`, `faq_open`.

Баннер не заменяет юридическую оценку: перед запуском проверьте политику с юристом.

## Что нужно сделать перед публикацией

1. Задать `SITE_URL`.
2. Заполнить в `/privacy/` места, отмеченные жёлтым маркером «ЗАПОЛНИТЬ ПЕРЕД ПУБЛИКАЦИЕЙ» (реквизиты оператора, основания, сроки, третьи лица).
3. Решить, как будет работать отправка формы (`FORM_ENDPOINT`), и обновить политику.
4. Заменить демонстрационные проекты реальными кейсами, если они появятся.
5. Положить файлы шрифта Inter в `public/fonts/` (сейчас используется системный запасной стек, поэтому сайт работает и без них).
6. Запустить `npm run build && npm run check`.
